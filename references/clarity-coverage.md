# Coverage · AI-Readability 分类法 (C1–C12)

本技能覆盖的 AI 可读性维度。✅ = 已覆盖；(强化) = 经迭代实质增强。

| ID | 维度 | 含义 | 状态 |
|----|------|------|------|
| C1 | 触发精度 | 何时该用写清楚、正负触发清单 | ✅ |
| C2 | I/O 契约 | 输入→输出显式；SOP 每步自带 I/O 契约 | ✅ |
| C3 | 步骤原子性 | 流动散文→原子步骤；类型化重排判定 | ✅ (R14 重排判定) |
| C4 | 失败模式显式 | 逐步失败恢复表 | ✅ |
| C5 | 前置后置条件 | 全局 + 类型化前置 | ✅ (R14 类型化前置) |
| C6 | 歧义消除 | 歧义点清单 + 逐条消解硬规则 | ✅ (R11 歧义消解) |
| C7 | 术语接地 | 术语表抽取 + 正文复用硬规则 | ✅ (强化·R9+R13) |
| C8 | 示例密度 | 四维 few-shot 改写前后对照模板 | ✅ (R12 few-shot) |
| C9 | 范围边界 | NON-mandate 在 §三 显式，转化版摘要含范围边界 | ✅ |
| C10 | 渐进披露 | 摘要前置 + 体量由可读性决定（不设行数硬上限） | ✅ |
| C11 | 简洁 / token 经济 | 以「简洁 / 不过度写 / 最好用」原则衡量；删冗余、不堆指标、不比倍数 | ✅ |
| C12 | 正面指令 | 否定词扫描→正面改写清单 | ✅ (R12 否定词清单) |

**缺口信号说明**：`coverage.md` 是缺口信号 `in_taxonomy` 的判断依据——没有它，agent 无法判断「这个值是不是我已经声明覆盖的」。某维度未在表中声明覆盖，却出现在真实技能里，即标记为待补维度，进入下一版转化清单。

**按技能类型的覆盖权重**（不降低任一维度的硬要求，只调整转化时的侧重点）：
- utility：C1 + C2 为主
- workflow：C3 + C4 为主
- coding：C2 + C3 为主
- persona：C7 + C8（保 voice，C3 弱化）
- agent：C9 + C4（委派边界、部分失败）
