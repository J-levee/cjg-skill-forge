# 技能写作规范（Skill Writing Guide）——锻造炉产出技能的 SKILL.md 写作标准

> **加载时机**：进入「模式 A 锻造 / 模式 D 清晰化」时由锻造炉读取本规范（按需加载，不常驻）。
> **定位**：锻造炉在锻造/升级任何技能（S0–S8、模式 D）时，SKILL.md 必须按本规范写作。它是「AI 易读」（模式 D）+「触发精度与渐进披露」（纪律 7）+「版本与披露范围」（纪律 15）的交汇执行标准。
> **目标**：用户和 Agent 都能 **30 秒读完 SKILL.md**、按需加载细节、**绝不因精简丢失必要内容**。
> **本文件本身就是范本**：锻造炉的 SKILL.md 按此规范重构（826 → 181 行）。

---

## 1. 文档结构（导航式 SKILL.md 模板）

SKILL.md 是**导航**，不是全文。推荐顺序：

| # | 区块 | 作用 | 必须内联？ |
|---|------|------|-----------|
| 1 | frontmatter（slug/name/displayName/version/**description=发现触发器**） | 元数据 + 触发 | ✅ |
| 2 | 一句话定位 + "本文件是导航版"说明 | 读者 5 秒定位 | ✅ |
| 3 | §零 进化燃料（隐私说明 + opt-in + 透明入口） | 用户知情 | ✅ |
| 4 | 快速上手（30 秒，核心步骤 ≤5 条） | 用户/Agent 立即能用 | ✅ |
| 5 | 何时使用（**触发词表**） | Agent 判断触发 | ✅ |
| 6 | 模式/功能路由表（进入条件→核心动作→引用） | 按需路由 | ✅ |
| 7 | 流程速查表（如 S0–S8） | 执行对照 | ✅ |
| 8 | **红线速查**（每条 1 行） | 安全底线 | ✅ |
| 9 | 结构与校验规则（简短） | 维护者 | ✅ |
| 10 | 资源索引（references 一句话说明） | 按需点读 | ✅ |
| 11 | NON-mandate（不做什么） | 防 creeping | ✅ |
| 12 | footer（来源 + 进化状态） | 注入三件套之二 | ✅ |

**规模目标**：SKILL.md ≤ 250 行（硬上限 600 行 / 5k 词，纪律 7）；细节全部下沉 references。

## 2. 文案披露范围（只写用户侧，不写生产侧）

> 与「版本日志规范」铁律一致：技能文档是给**用户和 Agent** 看的，不是给开发者看的。

**✅ 必须写（用户侧）**：
- 能力是什么、怎么用、触发词
- 红线、隐私说明、opt-in / opt-out 指令
- 平台品牌（如"藏经阁·易筋"——用户需要知道数据回传去哪）
- 方法论的**内容本身**（如纪律、模式、阶段）——这是能力，不是生产叙事
- **触发词（SEO）**：description 与「何时使用」表嵌入用户会搜的关键词——触发词=搜索流量，方法论见 `references/trigger-keywords.md`（纪律 7 扩展）

**❌ 禁止写（生产侧）**：
- **迭代代号**：Wave A/B/C、Phase 0/1/2 等内部批次名
- **版本更新史**："v2.x 新增"、"本次重构"、"从 X 行瘦身到 Y 行"等更新日志
- **内部模块代号**：churn_reflector、关④、工程代号
- **内部编码**：L2/L3/L4、C1–C7、E/C1–C6 等仅开发者可读的编号
- **开发侧细节**：架构、API、内部 Bug 修复、部署过程

**判断原则**：用户需要知道"这个技能**能做什么、怎么用、数据去哪、如何关闭**"，不需要知道"它**怎么迭代来的**"。拿不准就删。

## 3. 按需加载（渐进披露）

- **SKILL.md 只留**：路由 + 红线 + 用户可见内容（第 1 节"必须内联"列）。
- **细节下沉 references/**：模式细节、纪律全文、方法论展开、模板。
- 每个 references 文件**开头注明加载时机**（如"触发到对应模式时读取本文件相应章节，其余不必加载"）。
- **资源索引给每个文件一句话**，帮 Agent 决定"要不要读、读哪个"。
- 版本标注、更新历史等**只存在于维护侧**（如有需要放项目仓库，不放技能包）。

## 4. 不得跳过必要内容（精简的底线）

**精简 ≠ 删内容**。以下**必须内联在 SKILL.md**（不能依赖加载，否则可能被 Agent 跳过）：

| 必要内容 | 为什么必须内联 |
|---------|---------------|
| **硬红线 / 安全红线** | 依赖加载 = 可能被跳过 = 底线失守 |
| **触发词**（description + 何时使用表） | 触发错位技能就废了 |
| **注入三件套**：进化燃料（§零）+ footer + coverage.md 引用 | 增长飞轮结缔组织，缺一不可 |
| **关键命令引用**（校验/打包/发布） | Agent 执行入口 |
| **隐私与 opt-in / opt-out 说明** | 合规底线 |

其余内容（方法论细节、模板、长示例）可下沉 references。

## 5. 写作规范校验门（发布前必跑）

对最终 SKILL.md 跑以下检查，任一不过 → 退回重写：

- [ ] **规模**：≤ 250 行（硬上限 600 行）
- [ ] **无生产侧文案**：grep 无 `Wave [A-Z]` / `v2.x 新增` / `本次重构` / 内部模块代号 / 内部编码（L2/L3/L4、C1–C7 等）
- [ ] **触发词（含 SEO）**：description 用 "Use when..." 且含中文触发词；"何时使用"表存在；**description ≤1024 字符（W3a）；description 与触发词表互文命中 ≥3 个（W3b）**
- [ ] **红线内联**：安全/范围/合规红线在 SKILL.md 正文
- [ ] **注入三件套在**：§零 进化燃料（+opt-in 说明）、footer、coverage.md 引用
- [ ] **引用完整性**：SKILL.md 引用的每个 references 文件都存在，且资源索引有一句话说明
- [ ] **按需加载声明**：references 文件开头注明加载时机
- [ ] **发布工具校验**：`forge-publish.py --check` / 发布前校验通过

## 6. 发布版本说明（Release Notes）写作规范

> **披露范围铁律同样适用于发布时的版本说明**：用户在平台上看到的 changelog，和 SKILL.md 一样**只站用户侧**——说清楚"这次改了什么、对你有什么价值"，**简要**，不暴露生产侧文案。发布工具会在发布前自动校验（writing_gate.py --changelog），命中禁词即阻断。

**❌ 禁止写（生产侧文案，命中即发布被拦）**：
- 迭代代号：Wave A/B/C、Phase 0/1/2、L2/L3/L4、GAP-x、Bug#xx、T-CAP-xx、P0/P1/P2
- 内部模块/工程代号：churn_reflector、关④、C1–C7、E/C1–C6、CJG-EVO、scf/函数名
- 版本更新史与重构叙事："v2.x 新增"、"本次重构"、"从 X 行瘦身"、"升级云端字段"
- 开发侧细节：架构、迁移、SQL、部署、环境变量、内部修复过程

**✅ 必须写（用户侧）**：
- **改了什么**：用户能感知的能力变化（新增/改进/修复了哪个功能）
- **有什么价值**：对用户的好处（更准/更快/更省心/能做什么新的事）
- 一句话隐私/透明说明（如涉及数据或自动行为，按 GAP-3 透明原则明示）

**模板（2–5 条，每条一句，可加一句收尾透明说明）**：
```
v2.x.x：一句话总览（本版本最值得说的价值）。
- 新增「xx 功能」：现在可以…（价值）
- 改进「xx」：…更…（价值）
- 修复「xx」问题：…不再…（价值）
（如涉及）技能不会自动修改你的文件；自动改进仍由你审阅确认。
```

**正反对照（真实示例）**：

| ❌ 生产侧（会被发布工具拦下） | ✅ 用户侧 |
|---|---|
| v2.9.14：新增 Wave B 云端杠杆（需开启云同步）——「同步我的信号」L2 跨设备合并、「同类用法」L3 纯匿名聚合、「本周改进」L4 互惠回执；新增 P1 三指标（采纳率/平均修订轮数/重复反馈率）+ --with-cloud 云端补全；新增回归守卫 apply_guard.py（apply 前快照+CHANGELOG、落地后采纳率对比、一键回滚） | v2.9.14：开启云同步后，可以在多台设备间合并你的使用记录；成长报告新增「采纳率 / 平均修订轮数 / 重复反馈率」三项指标，看清技能是否越用越顺手；每次自动改进前都会留下快照与说明，效果变差可一键回退。技能文件仍不会被自动修改。 |

**校验**：发布工具（cjg-skill-publish.py / forge-publish.py）发布前自动跑 `writing_gate.py --changelog "文本"`，命中禁词 → 拒绝发布（`--force` 可明确接受）；过于简略/纯默认模板 → 警告提示补一句价值说明。

- 纪律 15（版本与文档同步）：本规范第 2、6 节（文档侧 + 发布侧披露范围）是其执行细化。
